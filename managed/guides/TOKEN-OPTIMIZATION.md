# Reasoning, context and cost

Use the installed runtime's supported controls and current provider terms. This guide
makes no fixed savings claim, model-price comparison or promise of automatic routing.
It does not change models, premium modes, schedules or subscription settings.

## Reduce unnecessary work first

- Use injected startup context; retrieve missing, task-relevant excerpts on demand.
- Keep one compact task checkpoint with links to evidence. Recover it before splitting
  or resetting a conversation; a reset that loses the task creates rework.
- Batch independent reads, keep dependent steps sequential, and reuse passing checks
  unless changes or failures justify another run.
- Use deterministic scripts for checks that need no judgment. Inspect existing tools
  before adding another agent, watcher or service.
- Delegate only when independent work or review provides a concrete benefit within the
  user's routing and budget permissions. Extra agents also consume context and tokens.

## Calibrate reasoning to the task

Use lighter reasoning for bounded routine work when supported and adequate; retain
strong reasoning for consequential releases, security-sensitive decisions and difficult
debugging. Preserve the selected model and existing defaults unless a change is authorized.
Do not enable premium speed modes to meet a “faster without more cost” request.

Measure ordinary live tasks rather than duplicating paid benchmark calls. Record the task
class, actual model/harness, reasoning setting, elapsed time, reported usage and corrections
or retries. Include failed attempts and missing telemetry. Compare similar tasks; do not
claim a causal speed or quality gain from unrelated examples or one short run.

Use a bounded pilot with a rollback condition. Change one setting at a time, scope it to
the intended session, and verify effective state. A session experiment does not authorize
changing all agents or scheduled jobs. End the pilot without a gain claim if evidence is
insufficient. Subscription usage and API spend are separate budgets.

## Verify capabilities instead of assuming them

Model prefixes, routing plugins, memory injection, prompt caching and compaction differ
by runtime. Inspect supported diagnostics. Do not query or edit internal databases as a
portable setup step. Never put gateway tokens in shell arguments or copied snippets.
For remote execution, verify the actual execution host and returned result; a child
session alone does not prove another machine performed the work.
